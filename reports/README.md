# reports/ — 백테스트 분석 리포트

수시 분석 결과와 그 **재현 코드**를 함께 보관한다.
스크립트는 모두 자기 위치(`SP = os.path.dirname(__file__)`) 기준으로 읽고 쓰므로
이 폴더에서 그대로 실행하면 된다.

## 260901 · 만능 스위치 반반 투자 성과 분석

이평선형(4일) + 중심주가형을 계좌당 $30,000씩 **50:50** 으로 굴렸을 때의 성과.

| 파일 | 내용 |
|---|---|
| `260901_만능스위치_반반투자_성과분석.html` | **최종 리포트** (브라우저로 열면 됨) |
| `combo.py` | 분석 본체 — 백테스트 3종 실행, 지표·히트맵 산출 |
| `mkreport.py` | `report_src.html` + 히트맵 + 연도별 표 → 리포트 HTML 조립 |
| `report_src.html` | 리포트 템플릿 (`__HEATMAP__`, `__YEARLY__` 자리표시자) |
| `combo_equity.csv` | 일별 자산곡선 3종 (이평4일 / 중심주가 / 합산) |
| `combo_stats.json` | 기간 3종 × 수수료 2종 = 6조합 지표 원자료 |
| `combo_heat.html` | 월별 히트맵 조각 (`common.analysis.monthly_perf_table` 출력) |

### 재현 방법

```bash
python combo.py      # 백테스트 → combo_equity.csv / combo_stats.json / combo_heat.html
python mkreport.py   # → report.html
```

`combo.py` 는 `common.pricedb.load_prices` 로 **로컬 종가 DB(무조정)** 를 읽는다.
야후(배당조정) 데이터로 돌리면 원본 구글시트와 결과가 달라지므로 바꾸지 말 것.

### 핵심 결론

- 합산의 위험조정수익(Calmar 2.85 / Sharpe 1.59 / Sortino 2.24)이 **두 전략 각각보다 높다.**
  기간 3종 × 수수료 2종 여섯 조합 전부에서 예외 없음.
- MDD −38.3% / −36.3% → **−32.7%**, 최악 하루 −22.3% / −23.8% → **−15.7%**.
- 일간수익률 상관 **0.67** (구간 판정 기준이 서로 달라서 생기는 분산 효과).
- 합산이 두 전략 중 못한 쪽보다 나았던 해 **16/16년**.
- 기대할 것은 더 높은 수익률이 아니라 **더 편안한 곡선**.

### 읽을 때 주의

- 2011~2015 SOXL 은 $0.6~$2 대라 1센트 호가가 가격의 0.5~1.4% → 이 구간 수익의
  상당 부분이 센트 반올림에서 나온다. **절대 수치는 2017년 이후를 볼 것.**
- 스프레드 미반영, 수용력(복리로 커진 계좌의 종가 체결 한계) 미반영.
- 단, 위 한계는 세 전략에 **똑같이** 걸리므로 **셋 사이의 상대 비교는 유효**하다.

## 260901 · 만능 스위치 비대칭 배분 분석

50:50 이 아닌 **비대칭 비중**(5% 단위)이 나은지 전수 검증.
총자본 $60,000 고정, 각 프리셋을 자본 5~100% 20단계로 미리 백테스트해
임의 비중 포트폴리오를 정확히 합성 (정수 주식수 반올림까지 반영).

| 파일 | 내용 |
|---|---|
| `260901_만능스위치_비대칭배분_분석.html` | **최종 리포트** (SVG 비중곡선 차트 포함) |
| `combo_weights.py` | 자본 20단계 x 4프리셋 x 3구간 백테스트 + 격자 전수 최적화 |
| `mkreport_weights.py` | 리포트 조립 (SVG 라인차트 생성 포함) |
| `report_weights_src.html` | 리포트 템플릿 |
| `weights_sweep2.csv` | 2종 조합 비중 스윕 (6쌍 x 3구간 x 19비중 = 342행) |
| `weights_best.csv` | 조합별 최적/균등 비중과 고원 비율 |
| `weights_oos_test.py` | **결정적 검증** — 훈련 최적비중을 검증구간에 적용 |
| `weights_oos_test.csv` | 위 스크립트의 결과 (mkreport_weights.py 가 읽음) |
| `weights_stats.json` | 지표 원자료 |

### 재현 방법

```bash
python combo_weights.py     # 백테스트 240회 (~6분)
python weights_oos_test.py  # IS 최적비중 → OOS 적용 검증
python mkreport_weights.py  # → 260901_만능스위치_비대칭배분_분석.html
```

### 핵심 결론

- **비중 최적화는 하지 말 것.** 훈련(2017~2023) 최적비중을 검증(2024~2026)에
  적용한 결과 **11개 조합 중 8개에서 균등배분에 패배**, 평균 **−12.3%**.
- 사후최적을 100 이라 할 때 회수율: **균등 96% vs 훈련최적 84%**.
- 실패 방식이 특징적 — 평소엔 조금 손해, 가끔 크게 틀림
  (`이평1일+RSI` RSI 95% 몰빵 → 검증 −42%, `이평1일+중심주가+RSI` → −44%).
- 최적 비중은 구간마다 뒤집힘. `이평4일+이평1일`: 전체 55:45 / 훈련 80:20 / 검증 **25:75**.
- **현재 운용 `이평4일+중심주가` 의 전체기간 최적 비중은 정확히 50:50** (균등 손해 0.0%).
- 프리셋을 많이 넣을수록 위험 증가 — 4종은 격자 969개에 고원비율 36% 로 가장 좁음.
- 리밸런싱 미검토, Calmar 기준(다른 지표면 최적점은 달라지나 불안정성은 동일).

## 260902 · 만능 스위치 티어 비율 분석

운용 중인 `이평4일 + 중심주가` 에서 **1티어/2티어 시드 비율**(현재 1%/99%)을
1~95% 전 구간 스윕. 25:75 등으로 바꾸면 어떻게 되는지.

| 파일 | 내용 |
|---|---|
| `260902_만능스위치_티어비율_분석.html` | **최종 리포트** |
| `tier_ratio.py` | 비율 스윕 (16비율 x 2전략 x 3구간) + 두 전략 비율 2D 격자 |
| `tier_detail.py` | 티어별 기여 분해 + 1% 미만 정밀 스윕 + 1주 하한선 검증 |
| `mkreport_tier.py` | 리포트 조립 |
| `report_tier_src.html` | 리포트 템플릿 |
| `_chart.py` | **공용 SVG 라인차트** (테마 토큰 대응) |
| `tier_sweep.csv` / `tier_grid.csv` | 스윕 결과 · 2D 격자 |
| `tier_bytier.csv` | 티어별 거래 특성 (거래/승률/보유일/손익비) |
| `tier_fine.csv` / `tier_floor.csv` | 1% 미만 정밀 · 계좌규모별 체결 건수 |

### 재현 방법

```bash
python tier_ratio.py && python tier_detail.py && python mkreport_tier.py
```

### 핵심 결론

- **1% 유지가 정답.** 전체/훈련/검증 세 구간, 두 전략 모두 1% 가 최적.
  앞선 두 리포트와 달리 **최적점이 구간에 따라 흔들리지 않는다** (구조적 단조 관계).
- 25:75 로 바꾸면 CAGR 93.2%→75.9%, MDD −32.7%→−44.4%, Calmar **−40%**.
  수익과 낙폭이 **동시에** 나빠짐 — 맞교환이 아님.
- **원인**: 비율을 바꿔도 거래 건수·승률은 한 건도 안 변한다. 금액만 바뀐다.
  1티어는 승률 89~91% 인데 손익비 0.17~0.32 (보유 5~8일).
  2티어는 승률 53~57% 에 손익비 1.22~1.74 (보유 하루 남짓).
  중심주가형 중간구간 1티어는 누적손익이 **마이너스**.
- **1티어는 포지션이 아니라 스위치.** `tier_method='보유'` 라 1티어가 1주라도 사야
  2티어가 열린다. 1% 는 "2티어를 여는 최소한".
- ⚠️ **1주 하한선** — 1티어 금액 < 1주 값이면 2티어가 영영 안 열림.
  계좌 $30,000 · 1% = $300 → SOXL $112.79 기준 2.7주 (정상).
  **SOXL 이 $300 넘으면 위험** (2024년 이후 최고 $300.77). 점검: 1티어 주문 수량 0주 여부.
  그럴 땐 2% 로만 올려도 여유 2배, 성적 손실 2% 남짓.
- 세 레벨 동일 비율만 검토 (레벨별 차등 미검토), 티어 개수·갭·손절일수는 고정.

## 260902 · 만능 스위치 1주 매수 비교

1티어를 **"시드의 1% 금액매수"** 대신 **"딱 1주 매수"** 로 바꾸면?

| 파일 | 내용 |

| `tier_oneshare.py` | 3변형(A 현재 / B 1주고정 / C 1주+게이트확대) 비교 + 수량·내성 분석 |
| `mkreport_oneshare.py` | 리포트 조립 |
| `report_oneshare_src.html` | 리포트 템플릿 |
| `oneshare_stats.csv/.json` | 변형 x 대상 x 구간 지표 |
| `oneshare_qty.csv` | 1티어 실제 체결 수량·투입액 |

### 재현 방법

```bash
python tier_oneshare.py && python mkreport_oneshare.py
```

⚠️ 엔진에 고정 수량 모드가 없어서 `manse_engine.calc_qty` 를 **분석 시점에만 가로챈다**
(`manse_engine.py` 는 수정하지 않음). `buy_amt = buy_px * qty` 라 현금·매도목표 회계는 그대로 따라간다.
레벨 옵션 `fixed_qty`(정량매수)는 이름과 달리 "사다리 없이 시드÷주문가"로 여전히 금액 기준.

### 핵심 결론

- **성과는 사실상 동일.** 전체기간 합산 Calmar 2.854 → 2.828 (−0.9%),
  개별은 오히려 근소 개선(이평4일 2.63→2.65, 중심주가 2.03→2.06). **부호가 엇갈림 = 무의미한 차이.**
- 1티어 누적 투입액은 **$310,539,711 → $6,921** (이평4일). 체결 건수는 283→286 로 거의 동일.
  → 1티어가 스위치일 뿐이라는 앞 리포트 결론의 재확인.
- **진짜 효과: 비율이 성과와 분리된다.** seed_w 를 1%→90% 올릴 때
  금액매수는 Calmar **−90%**, 1주고정은 **변화 0.000%** (완전 평평).
- ⚠️ **1주 고정만으로는 "$300 벽"이 안 없어진다.** 주문 자격(`odp > seed`)은 seed_w 가 결정하므로,
  $3,000 계좌에서 A·B 모두 2티어 167건(정상 277)으로 망가지고 **C만 정상 복귀**.
  → 수량 고정 + 비율 인상을 **같이** 해야 의미가 있다.
- 당장 바꿀 이유는 약함 — 성과 이득 없고 $30,000 계좌에선 벽도 아직 안 걸림.
  **SOXL 이 $250~300 에 다시 근접하거나 계좌를 쪼갤 때** 검토.
- 적용하려면 티어 설정에 "고정 수량" 옵션 추가가 필요 (현재 엔진·앱에는 없음).
